# Module Structure

A reusable Terraform module — whatever provider(s) it targets (AWS, GCP,
or others) — follows a consistent directory shape so any module in the
collection can be navigated the same way:

```
modules/<name>/
  main.tf         # resources
  variables.tf    # input variables
  outputs.tf      # output values
  versions.tf     # required_version + required_providers
  README.md       # generated by terraform-docs, not hand-edited
  examples/
    basic-usage/
      main.tf
      versions.tf   # required_version must match the module's own versions.tf
```

## Why a separate `examples/` directory

`examples/basic-usage/` is a minimal, runnable consumer of the module —
it's what a user copies to get started, and it's also what `tflint
--recursive` lints alongside the module itself. Keep it small: just enough
`main.tf` to instantiate the module with realistic inputs, not a
demonstration of every optional feature.

Each example carries its own `versions.tf` with a `required_version` that
matches the module's. An example missing this file, or pinning a different
version, is a common source of `tflint` warnings — see
[gotchas.md](gotchas.md).

## README generation

`README.md` is generated by `terraform-docs` from the module's `variables.tf`
/ `outputs.tf` and doc comments — don't hand-edit it. Regenerate it after
changing a variable or output so the documented API stays in sync with the
actual one.
